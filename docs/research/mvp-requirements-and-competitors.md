## 1. 競合比較表

調査対象: Duolingo / Anki / mikan / スタディサプリENGLISH (4件、いずれも2026年時点で活発な主要サービス)

| 観点 | Duolingo | Anki | mikan | スタディサプリENGLISH |
|------|----------|------|-------|----------------------|
| 位置づけ | ゲーム化総合語学アプリ (100M+ユーザー) | SRS暗記フラッシュカード (OSS・全プラットフォーム) | 英単語特化フラッシュ/クイズアプリ | 映像講義中心の英語資格対策サブスク |
| 主要機能 | 短時間レッスンの4択/リスニング/ライティング、ポイント・バッジ・仮想通貨、日課目標、リーグ、適応難易度 | フラッシュカード+間隔反復(SRS)。正解4段階(Again/Hard/Good/Easy)で次回復習日を自動計算。HTML/CSSでカード完全カスタマイズ。デッキ共有・同期 | 1回1分程度のフラッシュカード→間違えた単語を復習→4択テスト、単語ごとの音声、リマインド、コース(英検/TOEIC/受験)別、自動出題管理 | 有名講師の映像講義、実践問題集、ディクテーション/シャドーイング、AIアダプティブ講座、TEPPAN英単語(スキマ5分)、学習記録の可視化 |
| 強み | 継続装置が最強化 (ゲーム化・習慣化)。無料枠が充実。短時間で済む | 記憶効率の理論的最適 (忘却曲線ベース)。カスタマイズ性の高さは右に出るものなし。無料 (PC/Android) | 手軽さ・UIの良さ・褒める演出による継続しやすさ。紙の単語帳データと連携しやすい | 質の高い解説と4技能カバー。スコア成果と直結。満足度★4以上が約8割 |
| 弱み | 文法・文化の深掘りが浅い。語彙/初級への偏重。スピーキング練習不足。ゲーム化が「ゲーム自体をこなす」目的化の弊害 | デッキ自作が最大の離脱要因 (1000語入力は現実的でない)。iOSアプリが高額。UIが無機質でとっつきにくい | 英日一対一訳で語義の曖昧さが潰れる。英英辞書なし。正誤効果音が分かりにくい。単語帳機能のみ | 月額3,000円超の課金前提。自動歩行型（用意されたカリキュラムをこなす形式）の学習設計で自律学習者には過剰。試験対策に偏り日常会話力は付かない |
| MVPへの示唆 | 継続仕掛けは「スタンプ+日課目標」までを模倣、リーグ/社交機能は複雑化要因のため除外 | SRS(または簡易間隔反復)は語彙定着の中核。ただし「デッキ自作させない」ことが採用条件 | フラッシュカード+4択+音声の3点セットは最小の満足形態。1セッション=1分以内の設計 | 進捗記録は「見える化」されて初めて動機付けになる。スコア/週次サマリーなど簡易な可視化でよい |

## 2. MVP 機能スコープ

### 2.1 コア機能 (MVP に含める) — 優先度順

優先度: P0 = 必須 (なければ成り立たない) / P1 = 強い (あれば成功確率が上がる) / P2 = 今回含めないが設計上の拡張余地は残す

| ID | 機能 | 優先度 | 受け入れ基準 (要約) | 競合根拠 |
|----|------|--------|--------------------|----------|
| F1 | 単語フラッシュカード学習 (表: 見出し語 → 裏: 意味+例文) | P0 | 1デッキ10語以上を連続表示、タップでめくれる、1セッション1分以内で完了 | mikan/Anki の中核 |
| F2 | 4択クイズ形式テスト | P0 | フラッシュ終了後、誤答語+ランダム語で4択出題。選択肢は同一デッキから生成。正誤が音+色で明確に分かる | mikan のフロー。mikanの教訓「効果音が判別不能」は回避 |
| F3 | 簡易間隔反復 (誤答語を同じセッション内で再出題 / 翌日以降の復習キュー) | P0 | 誤答語はセッション末尾で必ず再出題。正解が続く語は翌日以降に間隔を伸ばして再登場 (完全なSM-2は不要、3段階で十分) | Anki の SRS が効率の中核。実装は簡略版で可 |
| F4 | 進捗記録・ダッシュボード | P0 | 学習日数、累計学習語数、正答率、昨日起動の有无。ローカルDBに永続化 | スタディサプリ「見える化がモチベ維持」、Duolingoの成績トラッキング |
| F5 | 日次目標とリマインド表示 (連続学習日数=スタンプ) | P1 | 「今日○語完了」の進捗バーと連続日数。Web通知は任意 (ブラウザ通知/単なる画面上表示で可) | Duolingo/mikan の継続装置。高度なリマインダー機構は最下層でよい |
| F6 | 単語デッキの取り込み (CSV/JSONインポート、既定サンプルデッキ同梱) | P1 | ユーザーがCSV(見出し語,意味,例文)を貼り付け/アップロードでデッキ化。初期デッキ(例: 中学基本850語相当)を同梱 | Anki教訓: 手入力させない。既定データを渡すことが離脱防止になる |
| F7 | 発音音声の再生 | P1 | カード/クイズ画面でワンタップ再生 (Web Speech API のTTSで実装可) | mikan「音声付きが覚えやすい」 |
| F8 | 誤答ノート (苦手語一覧の自動収集と手動フィルタ) | P1 | 誤答履歴から語彙一覧を生成、そこだけを再学習できる | Anki/mikan 共通の「苦手語に集中」ニーズ |

### 2.2 明確に除外する機能 (MVP スコープ外)

| 機能 | 除外理由 |
|------|----------|
| リーグ・ランキング・ソーシャル共有 | 開発コスト大。個人利用規模では動機付け効果が薄い (A3) |
| AI英会話 / チャットボット | 競合差別化には効くがMVPの検証目的 (語彙定着+継続) とズレる。API課金も発生 |
| スキミング/ライティング添削、発音採点 | 4技能すべてを最初から追うとスコープ破綻 (Duolingoでも弱みとされる領域) |
| 課金・サブスク | 個人利用 (A3)。Streakのリセット課金等も不要 |
| ネイティブアプリ、Android/iOS配布 | Web優先 (A2)。必要なら後日 PWA/ラッパーで対応 |
| 完全な SRS アルゴリズム (SM-2/FSRS) | F3の簡易版で検証してから升级判断。最適化は学習データが出てから |
| 映像講義コンテンツ | 制作コストが個人規模で現実的でない。テキストの解説文で代替 |
| 多言語・複数ユーザー | 英語学習に専念 (A1, A3) |

## 3. 非機能要求

| 観点 | 要求 | 妥協点 |
|------|------|--------|
| オフライン | 不要 (オンライン前提)。学習状態の永続化は LocalStorage/IndexedDB ベースならオフラインでも閲覧・学習継続は可能 | PWAキャッシュ化は P2 の拡張として設計にフックだけ残す |
| 認証 | 不要。ローカル保存のみで動作。同期/複数デバイス利用が必要になった時点で子タスク起票 | 学習データがブラウザ削除で失われる旨をUIに明記 |
| パフォーマンス | 初期ロード ≤ 3秒 (4G相当)、カードめくり・クイズ遷移は体感即時 (< 100ms) | 語彙データはデッキ単位の遅延ロードでよい |
| 対応環境 | 最新版 Chrome/Safari/Firefox + iOS/Android モバイルブラウザ。モバイル第一 (片手親指で完結) | IE/旧ブラウザサポートなし |
| アクセシビリティ | 正誤は色以外 (アイコン+テキスト+音) で判別可能にする (mikan への不満の直接対策) | 完全なWCAG準拠は目指さない |
| データ形式 | 語彙・進捗はスキーマ文書化済みJSON。将来のサーバー保存・他アプリ移行 (Anki CSV互換など) に対応できる形 | — |
| セキュリティ | 個人ローカル利用のため認証・TLS以外の特段の対策は不要。外部APIキーは埋め込まない設計 | TTSはブラウザ組み込み API を使い鍵管理を回避 |

## 4. MVP 成功基準 (受け入れ)

- 新規ユーザー (本人) がサンプルデッキで **初回セッションを 1分以内に完走** できる
- **連続7日** 使用し、誤答語が F3 のキューにより自然に再登場することを確認
- CSV取り込みで **100語デッキを 5分以内** に作成できる (Anki型の入力苦行が発生しないこと)
- 以上をもって「下流の設計タスクが迷わず着手できる具体度」を満たす

## 5. 下流タスクへの推奨

1. 設計タスクは F1〜F4 + データスキーマ (第3節 末尾) をスケルトンに、画面フロー(ホーム→デッキ選択→フラッシュ→クイズ→結果)から書く
2. 技術選定 (SPA框架/保存機構) は本レポートの制約 (ローカル保存・認証不要・モバイル第一) と矛盾しない範囲で実装者裁量に委ねてよい
3. §0 の Q1〜Q3 は設計着手前に発注者へ一括確認
